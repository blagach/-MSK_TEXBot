# Как предоставить доступ к проверке тестового бэкапа

Нужен доступ только к Shell сервиса **msk-texbot-test** в **My Workspace**. Доступ к рабочему сервису, его SQLite и токену не нужен. Сейчас фактическая копия не подтверждена; это блокирует deploy, но не локальную разработку.

## Вариант 1 — проверка агентом через безопасный вход

1. Напишите в этом чате, что готовы закончить безопасный вход в Render для проверки тестового бэкапа. Агент откроет защищённую форму входа; секреты в переписке не нужны.
2. Выберите привычный способ входа. Если выбираете GitHub, нужно закончить вход в GitHub и дождаться возврата в Render. Само нажатие «GitHub» ещё не означает вход в Render. Пароль и код вводятся только в защищённой форме входа или на странице сайта.
3. После входа должна быть доступна страница My Workspace → msk-texbot-test → Shell. Не нажимайте Manual Deploy, Restart, Delete и не меняйте Environment.
4. Сообщите: «Вход завершён, можно проверить только резервную копию тестового сервиса». Это разрешение на проверку, не на обновление.
5. Агент проверит ID сервиса, путь базы, новый снимок, SHA-256 и восстановление в отдельный файл. При отсутствии доступа или ошибке остановится и сообщит точный результат.

Подключённый Render-инструмент читает состояние сервиса, но не предоставляет доступ к файлам SQLite/Shell. Вход в Render в вашем отдельном браузере телефона сам по себе не авторизует браузер агента.

## Вариант 2 — проверка владельцем без передачи входа

1. Откройте Render в своём браузере и выберите **msk-texbot-test**, а не рабочий сервис.
2. Откройте Shell. Выполните шаги 1–5 из [инструкции проверки копии](tz7-test-release-readiness.md#точные-действия-владельца-для-проверки-копии-без-обновления).
3. При любой ошибке остановитесь. Не выполняйте восстановление поверх `/var/data/bot.db`, очистку или миграцию действующей базы.
4. Передайте только результаты: ID тестового Worker, пути снимка и восстановленного файла, SHA-256, успешное сравнение таблиц, количества записей и наличие №8/9/11/14. При необходимости скриншот должен содержать только эти результаты.
5. Пароли, токены, номера телефонов, саму SQLite и тексты обращений в чат не отправляйте. Результат будет обозначен как проверка владельцем, а не самостоятельная проверка агентом.

После подтверждения копии отдельно проверяются миграция на копии и совместимый откат. Только затем запрашивается отдельное письменное разрешение на точный тестовый коммит. C05/E01 остаются открытыми до ручной приёмки с двух аккаунтов.
