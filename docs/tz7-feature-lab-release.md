# Один будущий тестовый выпуск PR17

Это план, не разрешение и не выполненный Deploy. Production запрещён.
Точный SHA и CI фиксируются в приватном реестре и отчёте после завершения проверок.

## Что потребует отдельного решения владельца

1. Один Deploy точного согласованного SHA исключительно на msk-texbot-test.
2. Включение MSK_TEST_FEATURE_LAB=1 только там, без изменения секретов, ветки,
   Start Command или производственного сервиса.
3. Создание отдельного /var/data/feature-lab-test.sqlite с TEST-заказами,
   согласиями и fake-кампаниями. Бизнес-данные в /var/data/bot.db не мигрируют
   в платёжную модель; доступ к настоящим контактам остаётся бесплатным.
4. Свежий Backup API снимок основной тестовой SQLite и, если sidecar существует,
   отдельный снимок/восстановление sidecar. Старые копии сохраняются.

Флаг должен сохраняться способом, который не запускает автоматический Deploy.
Если это нельзя гарантировать, остановиться до изменения настройки и согласовать
другой порядок. «Save and deploy latest» или второй выпуск недопустимы.

## Предпроверки непосредственно перед изменениями

Точный service/bot/Live e64a079, история попыток, отсутствие параллельного Deploy,
один Worker, диск/место, integrity/FK, очереди/неопределённые исходы, текущие TESTER_IDS.
Подтвердить, что разрешение на этот новый кандидат ещё не использовано. При
неожиданном SHA, попытке, существенной ошибке или новых неизвестных исходах — стоп.
Сверить HEAD/полный SHA/CI. Production не меняется и не проверяется повторно без причины.

Уникальный каталог: свежий snapshot основной SQLite через Backup API, отдельный
restore, integrity/FK, все исходные строки/схема, размеры/SHA256/отчёт. Для
существующего sidecar выполнить то же. Не перезаписывать и не удалять файлы.
Перед командой повторно подтвердить актуальность снимка и отсутствие другого выпуска.

## Единственная команда

Сохранить одноразовое намерение; выполнить Deploy a specific commit полного SHA.
Не latest. При неопределённом результате только читать историю; команду не повторять.
При ошибке — диагностика и решение владельца, без автоматического отката.

## После запуска

Точный Live/DeployID/время, один Worker, прежняя бизнес-SQLite, исходные строки
профилей/заявок/откликов/техники/контактов/черновиков/настроек, очереди и старые
неопределённые исходы. Новых критических ошибок и дублей нет. Флаг включён только
в нужном service; demo-ограничения по умолчанию выключены, настоящий доступ
к контактам бесплатный. Sidecar отдельный, его backup/report проверены.

/lab — только владелец и допустимая маркетинговая роль; /checkout и /consent —
только разрешённые тестировщики с текущими прикладными правами. FakeTransport
не отправляет кампании в Telegram. Не создавать реальные заявки, не проводить
платежи и не выполнять настоящие рассылки. Уже принятые приветствие/iPhone/Web,
каталог и B04 не повторять.

Сначала автоматическая проверка установленного кода на отдельных копиях и
подставном транспорте. Затем короткая приёмка только новых экранов и целевых
переходов. Тариф и реальный платёжный режим этим не утверждаются.

## Совместимый возврат, только по новому решению

Предыдущий e64a079 не использует sidecar и совместим с прежней бизнес-схемой.
Возможный возврат кода требует отдельного разрешения и проверок, не выполняется
автоматически. Действующую SQLite старым снимком не заменять, sidecar/копии не
удалять. Исторические uncertain/unconfirmed не повторять.
