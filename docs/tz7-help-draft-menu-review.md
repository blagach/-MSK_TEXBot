## Тренировочная кнопка

Причина появления — постоянная строка `help:training` в `help:resources`.
Она открывала выбор роли, затем `help:train:*`/`help:try:*` и `show_training`.
Это прежний интерактивный учебный режим; его helper не создаёт реальные заявки.

Из меню убрана только эта кнопка. Остались четыре отдельные строки:
«Инструкции по ролям», «Частые вопросы», «Сообщить об ошибке», «В помощь».
Новой тренировочной кнопки нет. Все старые training/train/try callbacks
отклоняются до запуска сценария и не изменяют активную форму/черновики.
Предпринимается снятие старой клавиатуры; отказ Telegram не включает функцию.
Данные, TRAINING и helper-код сохранены, включая существующие внутренние проверки.

## Почему появляются несколько продолжений

`pause_form` сохраняет независимые auxiliary-слоты в существующем FSM SQLite.
`menu_with_paused_actions` ранее добавлял отдельную строку на каждый непустой
слот без проверки семьи состояния и текущих административных полномочий.
При этом обработчик возобновления проверял административные права: видимость
кнопки не означает возможности выполнить действие без прав.

Читающий аудит тестовой среды подтвердил пять реальных действий владельца.
Это сохранённые состояния, а не пять несуществующих ссылок или чужие черновики.
Другому обычному аккаунту принадлежит собственный черновик закрытия заявки.
Никакие состояния или роли при аудите не изменялись. Подробности остаются приватными.

Отдельно воспроизведён пробел ролевого меню: после отзыва роли на изолированной
фикстуре прежний код продолжает показывать административные продолжения.
Контроль выполнения остаётся, но критерий видимости по роли не выполнен.
Это основание вернуть B03 на проверку данного подкритерия, сохранив прежнюю
приёмку основных ролевых кнопок. По одному замечанию остальные статусы не меняются.
