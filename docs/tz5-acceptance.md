# MSK TEXBot · ТЗ‑5

## Заказчик

1. В тестовом боте нажмите «📋 Я заказчик» → «📝 Оставить заявку». Выберите категорию и вид техники.
2. Укажите регион, район и адрес. Ссылку на карту можно пропустить. Укажите дату и время, продолжительность и график смен, описание или «Пропустить описание», форму оплаты и телефон.
3. В предпросмотре выберите «✏️ Изменить данные» и проверьте нужное поле. После проверки нажмите «✅ Отправить на модерацию».
4. После одобрения откройте «📋 Мои заявки». В карточке можно посмотреть отклики, выбрать исполнителя, закрыть заявку с причиной или повторить её. Повтор открывает новый черновик. Исходная заявка сохраняется.
5. Для продолжения откройте «▶️ Продолжить заявку». В активной анкете команда /menu возвращает кнопки.

## Исполнитель

1. Нажмите «🚜 Я исполнитель» и зарегистрируйтесь. Через «➕ Добавить технику» заполните две разные карточки и проверьте их перед сохранением.
2. В «🚜 Моя техника» можно редактировать или приостанавливать единицы техники. Настройки уведомлений и оплаты доступны в меню исполнителя.
3. В «🔎 Подходящие заявки» отображаются опубликованные заявки по активной технике и зоне работы. Общий список остаётся в канале.
4. Нажмите «🚜 Откликнуться», заполните цену, условия и телефон. На проверке отклика можно поправить данные, отправить отклик или отменить именно этот черновик.
5. «📋 Мои отклики» показывает статус и результат доставки. «▶️ Продолжить отклик» открывает выбор сохранённого черновика.

## Контрольные действия с двумя аккаунтами

| Действие | Ожидаемый результат |
|---|---|
| Заказчик создаёт учебную для приёмки заявку на КДМ, исправляет одно поле в предпросмотре. Администратор публикует её | Одна публикация и одно уведомление заказчику. В канале видна сохранённая форма оплаты. Телефона и хештегов нет |
| Исполнитель с активной КДМ и подходящей зоной открывает список. Одна заявка по другому виду или зоне уже опубликована | Совпадающая заявка доступна. Несовпадающая остаётся в канале. При включённых уведомлениях приходит одно сообщение |
| Исполнитель открывает отклики на две разные заявки, переключает роль и возвращается. По одной заявке отправляет отклик и повторяет нажатие | Оба черновика открываются на своих шагах. По одной заявке хранится один отправленный отклик. Второй черновик остаётся доступным |
| Заказчик открывает отклики, выбирает исполнителя, закрывает с причиной и повторяет | Сохраняются выбранный отклик и причина. Повтор открывает новый черновик. Старые карточки и история остаются доступны |
| Пользователь отправляет обращение. Администратор отвечает. Пользователь отправляет уточнение | Пользователь получает отдельное сообщение. История видна обеим сторонам. При отказе Telegram администратор видит причину и подтверждение «Отправлено» не показывается |
| Администратор открывает статистику и XLSX. Обычный аккаунт пытается открыть админ-раздел | Счётчики видны администратору, в книге шесть листов. Обычный аккаунт не получает отчёт |
| На телефоне, Telegram Desktop и Web открыть /menu из формы, нажать устаревшую кнопку и пройти тренировку | Навигация доступна. Устаревшая кнопка не меняет сохранённые данные. Тренировка не создаёт заявки, отклики или уведомления |

## Ручная проверка после релиза 31d2e01

Использовать только @Msktex_test_dmitry_bot и два разрешённых Telegram-аккаунта. Для новых записей указать в описании или обращении метку «Приёмка 31d2e01», чтобы их можно было найти по истории.

1. **E01.** Обычный аккаунт создаёт новое обращение. Администратор отвечает в нём. На обычном аккаунте должны появиться отдельное уведомление, тот же текст по кнопке «Открыть обращение» и тот же ответ при повторном открытии из «Мои обращения». Записать номер обращения и отметить эти три результата. При недоставке сохранить статус и время, затем сверить историю без повторной отправки.
2. **№11 и №14.** С аккаунта исполнителя, у которого уже есть отклик на №11, открыть «Откликнуться» для №11 и убедиться, что новый отклик заблокирован. Открыть №14 и убедиться, что доступна отдельная форма. Если у проверяющего аккаунта нет прежнего отклика на №11, повторить эквивалентный сценарий на двух новых тестовых заявках. Для проверки финальной отправки и повторного нажатия использовать новую тестовую заявку.
3. **Меню и каталог.** С обеих ролей пройти группу и вид техники, вернуться к группам и нажать старую кнопку. Проверить, что старое действие ничего не меняет. В открытой анкете вызвать `/menu` и вернуться к тому же черновику. Повторить на телефоне и, при доступности, в Desktop или Web.
4. **Модерация, отклик и Excel.** На новой тестовой заявке пройти путь из таблицы выше. Сверить статусы в карточках и выгрузке. Обычный аккаунт не должен получить XLSX. Для фиксации результатов достаточно номера тестовой записи и статуса, личные контакты в отчёт не включать.

## Подготовка ручного тестового релиза

1. Дождаться отдельного разрешения владельца на конкретный SHA из `test/tz5-complete`. Зафиксировать результат GitHub Actions. В Render открыть только Worker `msk-texbot-test` (`srv-dboqc51srm7s73cppi00`). Сверить Live-коммит, отключённый автодеплой, отсутствие незавершённого релиза, диск `/var/data` и команду запуска `python render_test_start.py`. Для релиза 31d2e01 исходным Live-коммитом был `14a5b0c93f62445e590f268a239ce0c6f6b40b3b`. Перед следующим релизом сверить фактическое состояние. Ветка сервиса — `test/render-waste-pr9`, поэтому ручной запуск должен указывать точный SHA. Кнопку Deploy latest commit для этой операции не использовать.
2. Согласовать паузу в тестировании. Убедиться, что локальный polling остановлен. В Shell тестового Worker проверить наличие `/var/data/bot.db`, свободное место для новых снимков и восстановленных файлов. Сверить тестовые настройки и допустимые ID без вывода токена. При расхождении остановиться.
3. В Shell тестового Worker выполнить `python render_test_backup.py snapshot`. Записать точный путь, дату и SHA-256, сверить его через `sha256sum "$BACKUP"`, где `BACKUP` — путь из вывода. Восстановить в отдельный файл командой `python render_test_backup.py restore-candidate --backup "$BACKUP" --sha256 "$SHA256"`. Зафиксировать путь и контрольную сумму восстановленного файла. Физические суммы двух SQLite-файлов могут отличаться. Критерий равенства данных — совпадение всех исходных строк, успешные `integrity_check` и `foreign_key_check`.
4. На изолированной копии прогнать миграции именно кандидатом на релиз дважды. Сверить все строки и число записей в пользователях, профилях, технике, заявках, откликах, черновиках, обращениях, сообщениях и истории. Зафиксировать результаты без контактных данных. При ошибке хеша, восстановления, миграции или сверки развёртывание остановить. Снимок и копию сохранить.
5. В Render выбрать ручное развёртывание указанного коммита. Тестовый запуск сверяет имя Telegram-бота, ID Worker, закрытый канал, разрешённые аккаунты и диск SQLite. Он создаёт дополнительный снимок, восстанавливает отдельный файл, мигрирует его и сверяет исходные строки. До начала polling повторно сверяет исходные строки в тестовой базе. При ошибке запуска сохранить журнал и не повторять операцию без диагностики.
6. Проверить точный SHA, статус Live, отсутствие новых ошибок запуска и повторного polling. Пройти сценарии выше с двумя разрешёнными аккаунтами, включая E01. Успешный ответ Telegram API означает принятие сообщения API. Фактическое получение сообщения и наличие ответа в истории подтверждаются на аккаунте пользователя.

## Откат тестового релиза

- Цель отката — точный последний здоровый релиз, подтверждённый непосредственно перед обновлением. Перед откатом создать свежий снимок текущей тестовой базы, восстановить отдельный файл и проверить на нём совместимость предыдущего кода с новыми строками и черновиками. `6245c77` не умеет продолжать независимые черновики откликов.
- При успешной проверке совместимости откатить код на предыдущий SHA. Если совместимость не подтверждена, остановиться и сохранить оба снимка. Восстановление поверх текущего файла требует отдельного согласия и сверки записей, появившихся после старого снимка.
- Перенос на рабочую версию требует письменного разрешения и отдельной проверки рабочей базы, плана миграции и отката. Результаты тестовой приёмки приложить к запросу.
