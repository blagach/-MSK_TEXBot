# ТЗ №4. Помощь и поддержка

База — коммит 248508b. В главном меню строка с двумя ролями сохраняется. Под ней появляется «❓ Помощь / Поддержка». Вход из анкеты сохраняет её черновик по действующим правилам.

| Раздел | Сценарий |
| --- | --- |
| Как пользоваться ботом | Пошаговые инструкции заказчику и исполнителю, иллюстрации интерфейса, примеры заполнения |
| Попробовать на примере | Два интерактивных сценария с вымышленными данными. Тренировка не создаёт заявки, отклики, обращения и уведомления |
| Частые вопросы | Список тем и поиск по заголовкам, текстам и синонимам |
| Написать в поддержку и Сообщить об ошибке | Текст, необязательный скриншот, явное подтверждение, номер и история обращения |
| Очередь поддержки | Доступ только по ADMIN_IDS. Администратор берёт обращение в работу, отвечает через бота или закрывает |

В SQLite добавляются отдельные таблицы обращений и сообщений. История и статусы сохраняются без удаления записей. Скриншоты хранятся как идентификаторы файлов Telegram. Пользователь видит только свои обращения. Повторное подтверждение не создаёт дубль.

Уведомления администрации по умолчанию приходят в личный чат с ботом. Закрытая группа подключается настройкой SUPPORT_GROUP_ID, а в изолированном тестовом запуске — TEST_SUPPORT_GROUP_ID. Требуются права администратора у бота и группа только для разрешённых администраторов. В группу уходит только номер и тип обращения. Текст, скриншоты и действия доступны в личном чате с ботом. При неверной настройке группы уведомления остаются в личных чатах. Подключение группы и развёртывание выполняются по отдельному разрешению.

Иллюстрации — схемы актуального интерфейса с демонстрационными данными. Отображение в Telegram проверяется после разрешённого тестового развёртывания.

## Админ-панель

Отдельная точка входа для ADMIN_IDS. Списки пользователей и техники формируются по имеющимся записям. Заказчики учитываются по заявкам, исполнители по регистрациям или откликам. Два формата профилей объединяются по Telegram ID. Первые заявки и регистрации показываются отдельно. Периоды — календарные день, неделя и месяц по Москве.

В базе заявок есть состояния new, publishing, published и rejected. Отдельных операций закрытия и архивирования в текущем боте нет. В отчёте показываются фактические состояния, в том числе закрытые и архивные, если такие записи присутствуют. У откликов отдельно показывается доставка. Активность отклика определяется статусом связанной заявки, поскольку собственного жизненного цикла у откликов пока нет.

Выгрузка XLSX содержит отдельные листы «Пользователи» и «Техника». Telegram ID передаются как текст. Контактные номера и переписка в выгрузку не включаются. Панель не изменяет пользователей, заявки, отклики, технику и их статусы. Работа с обращениями доступна из панели и ограничена ответом и сменой статуса.
