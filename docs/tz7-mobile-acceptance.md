# Одна комплексная мобильная проверка кандидата

Не выполнено. Нужен отдельный разрешённый релиз тестового бота; текущий установленный бот не доказывает внешний вид нового кандидата. Синтетические сообщения и макеты не выдавать за реальные скриншоты. C05 уже принят и повторно не проверяется.

## Минимальный сеанс двух аккаунтов после разрешённого обновления

A — заказчик, B — администратор и зарегистрированный исполнитель. Если у B нет профиля исполнителя, владелец один раз регистрирует его и выбирает подходящие вид техники/регион; прочие технические проверки выполняет агент. Личные действия в Telegram:

1. A создаёт одну учебную заявку на будущую дату с известным ему номером телефона, обычным адресом и при желании картой. На предпросмотре проверяет поля и отправляет на модерацию.
2. B публикует эту заявку в тестовом контуре. Проверяет подходящее уведомление, нажимает «📞 Получить контакт заказчика» и сравнивает номер с A. Цена и длинный отклик не требуются.
3. B повторно открывает контакт. Агент технически сверяет одну запись доступа и отсутствие нового отклика/дубля уведомления; владелец только подтверждает правильность экрана.
4. На этой новой учебной заявке выполнить закрытие один раз для проверки нового контакта; B снова открывает ранее полученный контакт — он остаётся доступен. Это проверка нового сценария контакта, не повторная приёмка C05. Заявку прежней приёмки C05 не менять.
5. B открывает подготовленную агентом ссылку контакта другой, уже закрытой заявки, которую ранее не открывал: новый доступ запрещён. Агент подбирает ссылку и сверяет отсутствие новой записи. Блокировки, отсутствие регистрации и чужие данные проверены автоматически; изменять реальные роли/блокировки ради этого сеанса не нужно.

Агент до и после сеанса сверяет SQLite/аудит/очереди и счётчики только для чтения, готовит ссылки и кратко фиксирует результат. Владельцу не требуется вводить SQL, работать в GitHub или запускать Shell. При неожиданном результате повторно кнопки не нажимать; сохранить экран и сообщить шаг.

## Дополнительная визуальная сверка в том же сеансе

| Роль | Действия | Критерий |
|---|---|---|
| Заказчик | Каталог: длинное название, возврат к группе | Видно полное название, 10 групп/43 позиции, возврат сохраняет остальные данные |
| Заказчик | Адрес → точка карты → Назад → Пропустить → дата | Адрес не теряется, Яндекс Карты открываются, переходы понятны |
| Заказчик | Изменить поле на предпросмотре, menu/продолжить | Поля восстановлены; прежняя кнопка не отправляет заявку повторно |
| Заказчик | Прошедшая дата, затем будущая, отправка | Ошибка не теряет анкету; номер и статус видны после отправки |
| Администратор | Новая заявка → карточка → публикация | Контакты не видны публично, заказчик получает правильное уведомление |
| Исполнитель | Подходящее уведомление → контакт → повторное открытие | Нет обязательной анкеты отклика, виден правильный номер, черновик другой операции не теряется |
| Исполнитель | Длинная карточка и точка карты | Адрес и ссылка доступны, кнопки читаемы и не обрезаны |
| Администратор | Статусы поддержки и XLSX | Счётчики верны, выгрузка открывается; повтор не вызывает повторную отправку |
| Обе роли | Как пользоваться, последний шаг, восстановление | Названия совпадают с интерфейсом, кнопка завершения есть, нет тупика |
