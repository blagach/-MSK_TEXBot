# B05: сохранение прежней анкеты исполнителя

В установленном 6e334c56 исторический путь provider_legacy:edit открывает
ProviderForm.equipment/location/phone. pause_form не распознаёт эти три состояния
и вызывает state.clear() без сохранения. Поэтому переход /menu теряет ввод.
Проверка воспроизвела потерю на каждом из трёх шагов в изолированной SQLite.

Исправление использует существующий механизм незавершённых действий, отдельный
слот legacy_provider и кнопку «Продолжить прежнюю анкету». Она появляется только
при наличии такого черновика, участвует в принятой компактной группировке.
Отдельный слот сохраняет независимость новой регистрации, заявки и старой анкеты.
Продолжение восстанавливает исходный вопрос, а повторный вход в прежнюю анкету
возвращает текущий шаг вместо очистки. Чужая активная форма не меняется старой
кнопкой продолжения, если сохранённого legacy-действия нет.

Одна адресная регрессия проверяет три шага: /menu, закрытие/повторное открытие
SQLite-хранилища, продолжение через старый вход и новую кнопку, повторное
нажатие, сохранность современных черновиков, исходного профиля, схемы и всех
бизнес-строк. На исходном коде три подслучая падают, после исправления проходят.
Новые таблицы, миграции, удаление или сброс состояний не требуются.

До отдельно согласованного Deploy исправление существует только в кандидате.
A18/A20, справку, оплату, /lab и принятые сценарии повторять не нужно.

Для будущего тестового выпуска: exactservice/Live/history, отсутствие другого
Deploy, один Worker, место/очереди/unknown, свежие Backup API snapshot/restore
обеих SQLite, integrity/FK/схемы/все исходные строки/размеры/SHA256. Один точный
SHA, без latest, без env-изменений. После установки — сохранность данных и
адресная проверка установленного обработчика на отдельных копиях. Основные
действующие сценарии и TEST-уведомления ради этой проверки не создавать заново.

Возврат кода — только по отдельному разрешению, без замены действующей SQLite
старым снимком. Предыдущий код сохраняет неизвестные строки form_drafts, но
не показывает новый слот legacy_provider; перед любым возвратом отдельно
зафиксировать такие незавершённые действия. Старый дефект при возврате также
вернётся. Автоматический откат запрещён, данные и копии не удалять.
