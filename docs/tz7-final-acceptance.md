## Исправление пустой кампании

Запрет подтверждения нулевой аудитории правильный и сохранён. Предпросмотр теперь
показывает: «Нет получателей с действующим согласием для выбранного сегмента.
Подтвердить кампанию нельзя. Измените сегмент или сохраните черновик.»
Кнопки подтверждения нет. Старая кнопка той же пустой версии также безопасно
отклоняется этим сообщением, ничего не записывая. Чужие/устаревшие nonce проходят
прежнюю проверку. Черновик 23903a7a… не изменялся.

Прежняя инструкция Work ошибочно предлагала подтвердить кампанию с нулевой
аудиторией, хотя ядро уже запрещало это. Это ошибка инструкции, не пользователя.
На установленном тестовом боте после будущего разрешённого обновления достаточно
открыть существующий предпросмотр и увидеть объяснение/отсутствие подтверждения.
Не добавлять реальных получателей для обхода защиты.

Полный ненулевой цикл уже проверен на отдельной Backup API копии ранее полученной
тестовой sidecar: два условных адресата, будущее время МСК, owner approval,
пауза/продолжение, отзыв одного согласия, один fake sent и один excluded,
перезапуск и отсутствие повтора. Telegram-вызовов ноль. Исходный файл не менялся;
26 прикладных таблиц (27 с sqlite_sequence), исходные схемы и бизнес-строки
сохранены; финансовые таблицы точно совпадают, paid/остаток3 и прежний draft
сохранены. Изменён только ожидаемый счётчик скорости fake runtime и добавлены
условные данные нового сценария. integrity=ok, FK=0.
Это локальная ранее полученная копия, не свежий снимок действующего Render.
Совместимость основной SQLite подтверждается регрессией на изолированных
бизнес-копиях; текущий патч не меняет её схему. Перед будущим Deploy всё равно
нужны свежие снимки обеих действующих тестовых SQLite и проверка восстановления.
