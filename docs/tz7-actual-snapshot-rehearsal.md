## Подготовленный инструмент

`sqlite_rehearsal.py` работает из отдельного полного локального Git-репозитория с установленными
зависимостями. Сам не загружает код из сети, не устанавливает пакеты, не меняет ветки и Render.
Нужные точные коммиты должны уже присутствовать в этом репозитории.

```bash
python -B sqlite_rehearsal.py \
  --snapshot /var/data/backups/test-20261111T165141677395Z.sqlite \
  --sha256 'ПОЛНАЯ_СТРОКА_SHA256_ИЗ_ИСХОДНОГО_JSON' \
  --candidate a5f4eb98877c56fe384b55ff212081af485dee2c \
  --rollback cec41d17431c458aafb54242397116c419246848 \
  --evidence-parent /var/data/backups
```

Это шаблон для подготовленного отдельного checkout, не команда для немедленной вставки
в старый каталог установленного Worker: там нового инструмента нет. Обновлять Worker ради
получения инструмента запрещено. После доступа к Shell подготовить отдельный каталог с кодом
проверки и сверенными ревизиями; установленный каталог приложения не менять.

Инструмент проверяет переданный SHA-256, создаёт новый приватный каталог `sqlite-rehearsal-*`,
извлекает точные версии кода и восстанавливает снимок в новый `working.sqlite`.
Цикл: кандидат → кандидат → откат → откат → кандидат. После первого шага сохраняет ещё один
снимок мигрированной копии. После каждого шага сравнивает все исходные строки, включая дубли,
и все строки мигрированного снимка; проверяет целостность и внешние ключи. Хеш исходного снимка
сверяется на каждом шаге. Все таблицы, в том числе журнал, пользователи, заявки, отклики и черновики,
проверяются автоматически, даже если таблица не перечислена в специальном списке.

Дочерний процесс получает фиктивные настройки без действующих токенов, dotenv отключён;
аудит Python запрещает сетевые подключения, запуск дочерних программ и SQLite-подключения
к любому файлу, кроме новой рабочей копии. Вызывается только init_db/init_schema, без start(),
startup диспетчера, polling, Telegram и восстановления очередей отправки.
Отчёт содержит только пути, хеши, количества и ревизии. Файлы сохраняются и при ошибке.

Ограничение: это проверка инициализации схемы и сохранности всех строк. Она не подменяет
проверку поведения интерфейса, чтение фактических черновиков и ручную приёмку C05/E01.

## Текущая готовность

Фактический прогон миграции/отката **не выполнен**: браузер агента показывает вход Render,
а connector не даёт Shell или доступ к SQLite. Нужны доступ к Shell тестового Worker
и полная строка SHA-256. Вход владельца в его отдельном браузере не авторизует браузер агента.
Синтетические тесты инструмента не являются подтверждением фактического прогона.

Развёртывание не разрешено. Не менять действующую БД, установленный Worker, рабочий бот,
ветку и настройки Render. C05/E01 открыты. Финансы и рассылки не активируются.
