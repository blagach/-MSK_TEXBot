# MSK_TEXBot

Telegram-бот для заявок на спецтехнику в Москве и области. Python 3.12, aiogram, SQLite.

## Railway: постоянный запуск

1. В Railway создайте проект: Deploy from GitHub repo → `blagach/-MSK_TEXBot`. При необходимости разрешите Railway доступ к этому репозиторию в GitHub.
2. Добавьте к сервису Volume с Mount Path `/data`. Он хранит базу заявок между перезапусками. Используйте один экземпляр сервиса; база SQLite рассчитана на этот вариант запуска.
3. В Variables задайте:
   - `BOT_TOKEN` — токен из @BotFather. Вводите только в защищённых настройках сервиса.
   - `ADMIN_IDS` — числовой Telegram ID администратора; несколько ID через запятую.
   - `LEADS_CHANNEL_ID` — числовой ID канала, обычно начинается с `-100`.
   - `BOT_USERNAME` — точный username бота из @BotFather без `@`.
   - `DATABASE_PATH` — `/data/bot.db`.
4. Добавьте бота в канал администратором с правом публикации сообщений. Каждый администратор из `ADMIN_IDS` должен открыть бота и отправить `/start`, иначе бот не сможет прислать ему заявку.
5. Выполните Deploy. Команда запуска задана в `railway.toml`: `python bot.py`. Публичный домен и HTTP-порт не нужны: бот использует polling.
6. В логах ожидаются сообщения `Telegram: ... публикация разрешена`, затем запуск polling. Проверьте в Telegram: `/start` → «Оставить заявку» → заполнение → публикация администратором → отклик исполнителя.

Railway требует оплаты для постоянной работы; актуальную стоимость проверьте перед подключением тарифа. Нужен тариф с Volume. Если база уже существует на другом хостинге, перенесите её на Volume перед запуском, остановив старый экземпляр.

## Локальная проверка

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Заполните .env своими настройками.
python bot.py --check
python bot.py
```

В Windows активация: `.venv\Scripts\activate`. Локально оставьте `DATABASE_PATH=bot.db`.

`--check` проверяет токен, username, канал, право публикации, отсутствие webhook и доступность SQLite. Команда не отправляет сообщения и не запускает polling, но создаёт таблицы в выбранной БД.

## Если запуск не удался

- `Заполните BOT_TOKEN...`: добавьте обязательные переменные.
- `Unauthorized`: проверьте токен в настройках сервиса.
- `chat not found`: проверьте числовой ID канала и членство бота.
- Ошибка username: перенесите точное имя из @BotFather в `BOT_USERNAME`.
- `Conflict ... getUpdates`: остановите другую запущенную копию бота.
- Ошибка webhook: остановите прежний webhook-сервис и отключите webhook перед переходом на polling.
- `unable to open database file`: проверьте подключение Volume `/data` и путь `DATABASE_PATH`.
- Администратор не получает заявки: он должен сначала отправить боту `/start`.

Незавершённые анкеты хранятся в памяти и теряются при перезапуске. Готовые заявки и исполнители сохраняются в SQLite. Для базы нужны регулярные резервные копии.
